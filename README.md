# سازه‌شاپ — فروشگاه اینترنتی صنعت ساختمان (PHP + PWA)

فروشگاه آنلاین کامل با **PHP خالص** (بدون فریم‌ورک، بدون Composer و بدون مرحله build)،
دیتابیس **SQLite**، رابط کاربری **فارسی/راست‌به‌چپ** با ظاهر مینیمال و **PWA** قابل نصب روی گوشی.

الگو و ساختار صفحات با الهام از فروشگاه‌های صنعت ساختمان (مثل یابان) طراحی شده است:
دسته‌بندی، صفحه محصول با مشخصات فنی، پیشنهاد شگفت‌انگیز با شمارنده، سبد خرید،
پرداخت، پیگیری سفارش و پنل مدیریت.

---

## ۱. امکانات

### فروشگاه
- صفحه اصلی: اسلایدر هیرو، دسته‌بندی‌ها، پیشنهاد شگفت‌انگیز با شمارنده معکوس، پرفروش‌ها، جدیدترین‌ها، برندها
- صفحه دسته‌بندی با فیلتر **برند، بازه قیمت، موجودی** و مرتب‌سازی (جدیدترین، ارزان‌ترین، گران‌ترین، محبوب‌ترین، بیشترین تخفیف)
- صفحه محصول: گالری تصاویر، تب‌های توضیحات/مشخصات فنی/دیدگاه‌ها/ارسال و گارانتی، محصولات مشابه
- جست‌وجو با پیشنهاد لحظه‌ای (AJAX) و جست‌وجو در برند و کد کالا
- سبد خرید بدون رفرش (AJAX) + کد تخفیف + محاسبه هزینه ارسال و ارسال رایگان
- فرآیند پرداخت: اطلاعات گیرنده، آدرس‌های ذخیره‌شده، روش ارسال، پرداخت آنلاین (درگاه شبیه‌سازی‌شده) یا پرداخت در محل
- پیگیری سفارش با کد سفارش یا شماره موبایل + نمای وضعیت سفارش
- حساب کاربری: ثبت‌نام، ورود، سفارش‌های من، آدرس‌ها، ویرایش اطلاعات
- صفحات درباره ما، تماس با ما (فرم ذخیره‌شده در پنل)، سؤالات متداول، قوانین
- PDF/چاپ فاکتور با پرینت مرورگر، نقشه سایت XML، robots.txt، متا تگ‌های SEO

### پنل مدیریت (`/admin`)
- داشبورد: فروش ماه، نمودار فروش ۷ روز اخیر، سفارش‌های امروز، کالاهای کم‌موجود، آخرین سفارش‌ها، پیام‌ها
- محصولات: فهرست + فیلتر + افزودن/ویرایش (قیمت، تخفیف، موجودی، مشخصات فنی، گالری، **آپلود تصویر**) و غیرفعال‌سازی
- دسته‌بندی‌ها: افزودن/ویرایش/حذف با آیکون، تصویر، ترتیب
- سفارش‌ها: فیلتر بر اساس وضعیت، جست‌وجو، جزئیات کامل، تغییر وضعیت و ثبت کد رهگیری مرسوله
- مشتریان: تعداد سفارش و مجموع خرید هر مشتری
- کدهای تخفیف: درصدی یا مبلغ ثابت، حداقل سفارش، سقف استفاده، تاریخ انقضا
- پیام‌های فرم تماس
- تنظیمات: نام و شعار سایت، اطلاعات تماس، شبکه‌های اجتماعی، هزینه ارسال، درگاه پرداخت، متن درباره ما

### PWA (نصب روی گوشی)
- فایل `manifest.webmanifest` با نام، آیکون‌های ۱۹۲/۵۱۲/maskable و میان‌برهای سریع
- سرویس‌ورکر (`sw.js`): کش فایل‌های استاتیک، صفحه‌های دیده‌شده و تصاویر + صفحه آفلاین
- دکمه «نصب اپلیکیشن» در هدر و منوی موبایل (با پشتیبانی `beforeinstallprompt`)
- نوار ناوبری پایین صفحه در موبایل + پشتیبانی از safe-area آیفون
- حالت آفلاین: نمایش صفحات ذخیره‌شده و بنر هشدار قطعی اینترنت

## ۳. نصب روی هاست واقعی (cPanel / DirectAdmin)

> ❗️ **«فایل index.php کجاست؟»**
> نقطه ورود برنامه `public/index.php` است (نه ریشه پروژه) و صفحه‌ی خانه یک فایل HTML
> ثابت نیست؛ محتوای خانه از `app/views/home.php` و کنترلر `app/controllers/shop.php`
> ساخته می‌شود. آدرس صفحه خانه هم به‌صورت `/` نمایش داده می‌شود (URL تمیز) — دقیقاً مثل
> وردپرس که `/index.php` را در آدرس نشان نمی‌دهد. اگر `/index.php` را هم باز کنید،
> همان صفحه خانه را می‌بینید.

سه حالت نصب پشتیبانی می‌شود؛ فقط حالت ۱ (یا ۲) را انتخاب کنید:

| حالت | DocumentRoot | htaccess | آدرس‌ها | نیاز به کار خاص |
|---|---|---|---|---|
| ۱ (توصیه‌شده) | `public/` | `public/.htaccess` | `/cart` | تنظیم DocumentRoot دامنه |
| ۲ | ریشه پروژه | `.htaccess` ریشه (فعال) | `/cart` | فقط آپلود در ریشه |
| ۳ | ریشه پروژه | `.htaccess` غیرفعال | `/index.php/cart` | هیچ‌چیز؛ فایل `index.php` ریشه کار را انجام می‌دهد |

**مراحل نصب:**

1. همه فایل‌های پروژه را در سرور آپلود کنید (مثلاً `/home/USER/sazehshop`).
2. حالت نصب را انتخاب کنید:
   - **حالت ۱ (توصیه‌شده):** **DocumentRoot** دامنه را روی پوشه `public/` تنظیم کنید
     (هنگام ساخت دامنه در cPanel، روت را `sazehshop/public` بدهید).
   - **حالت ۲:** اگر دسترسی به DocumentRoot ندارید، پروژه را داخل `public_html` آپلود
     کنید؛ فایل `.htaccess` ریشه درخواست‌ها را به `public/` هدایت می‌کند.
   - **حالت ۳:** اگر `mod_rewrite` یا `.htaccess` روی هاست غیرفعال است، فقط کافی است
     سایت را با آدرس ریشه (`https://example.ir/`) باز کنید. فایل `index.php` ریشه
     نقطه ورود می‌شود و لینک‌ها خودکار به شکل `/index.php/cart` ساخته می‌شوند
     (فایل‌های استاتیک از `/public/...` خوانده می‌شوند).
3. دسترسی نوشتن را بدهید:
   ```bash
   chmod -R 755 storage public/uploads
   ```
   (روی بعضی هاست‌ها `775` لازم است)
4. آدرس سایت را باز کنید. **دیتابیس به صورت خودکار ساخته و با داده‌های نمونه پر می‌شود**
   (فایل `storage/shop.sqlite`). برای نصب دستی می‌توانید محتوای `database/schema.sql` را
   در phpLiteAdmin یا SQLiteStudio اجرا کنید و سپس `database/seed.php` را صدا بزنید.
5. در `app/config.php` مقدار `debug` را روی `false` بگذارید.
6. وارد `/admin` شوید و رمز حساب مدیر را تغییر دهید (از پنل یا با ویرایش دیتابیس).

### حساب‌های نمونه (بعد از نصب خودکار)
| نقش | ایمیل | رمز |
|---|---|---|
| مدیر | `admin@sazehshop.ir` | `admin1234` |
| مشتری | `demo@sazehshop.ir` | `demo1234` |

> ⚠️ پیش از انتشار روی دامنه واقعی، هر دو رمز را تغییر دهید.

### نمونه کانفیگ Nginx
```nginx
server {
    listen 80;
    server_name example.ir;
    root /home/USER/sazehshop/public;
    index index.php;

    location / { try_files $uri $uri/ /index.php?$query_string; }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
    }

    location ~* ^/(app|database|storage|tools)/ { deny all; }
    location ~* \.(sqlite|log|sql)$ { deny all; }
}
```

## ۴. اجرای پیش‌نمایش محلی (بدون نصب PHP)

در این پروژه یک سرور توسعه نوشته شده که PHP 8.3 را از طریق **WebAssembly** اجرا می‌کند؛
یعنی برای دیدن سایت روی سیستم خودتان فقط به **Node.js 20+** نیاز دارید:

```bash
npm install
npm run dev          # http://localhost:8080
```

برای تست حالت «DocumentRoot روی ریشه پروژه» (بدون .htaccess) هم می‌توانید اجرا کنید:

```bash
SHOP_DOCROOT=root PORT=8090 npm run dev
```

این سرور (`tools/dev-server.mjs`) فقط برای پیش‌نمایش و توسعه است و روی هاست واقعی
استفاده نمی‌شود. اگر PHP روی سیستم شما نصب است، می‌توانید همان کد را با سرور داخلی PHP هم اجرا کنید:

```bash
php -S localhost:8080 -t public
```

```

├── app/
│   ├── bootstrap.php        راه‌انداز: تنظیمات، نشست، CSRF، اتصال دیتابیس
│   ├── config.php           تنظیمات اصلی (اینجا را ویرایش کنید)
│   ├── helpers.php          توابع کمکی (قیمت، تاریخ شمسی، URL، امنیت خروجی)
│   ├── icons.php            آیکون‌های SVG درون‌خطی
│   ├── db.php               لایه PDO + نصب خودکار دیتابیس
│   ├── repo.php             کوئری‌های کاتالوگ، سفارش و آمار
│   ├── cart.php             سبد خرید، کد تخفیف و محاسبه ارسال
│   ├── auth.php             ورود/ثبت‌نام/دسترسی‌ها
│   ├── csrf.php / flash.php توکن CSRF و پیام‌های موقت
│   ├── router.php           جدول مسیرها
│   ├── views.php            موتور قالب
│   ├── controllers/         کنترلرهای فروشگاه و پنل مدیریت
│   └── views/               قالب‌های HTML (layout + صفحات + partials)
├── database/
│   ├── schema.sql           ساختار جدول‌ها
│   └── seed.php             داده‌های نمونه (دسته‌بندی، محصول، سفارش، تخفیف)
├── public/                  ← ریشه وب (DocumentRoot)
│   ├── index.php            تنها نقطه ورود
│   ├── .htaccess            URL های تمیز، هدرهای امنیتی، کش
│   ├── manifest.webmanifest / sw.js / offline.html
│   ├── robots.txt
│   └── assets/{css,js,img,fonts,icons}
├── storage/                 دیتابیس، نشست‌ها و لاگ‌ها (باید قابل نوشتن باشد)
├── tools/dev-server.mjs     سرور پیش‌نمایش (php-wasm)
├── index.php                ورودی جایگزین (هاست‌های بدون .htaccess)
└── .htaccess                ریدایرکت به public (برای هاست‌های بدون دسترسی به روت)
```

## ۶. نکات فنی

### دیتابیس
- مسیر فایل دیتابیس در `app/config.php` → `db_file` قابل تغییر است.
- در `app/db.php` حالت WAL فعال است؛ فایل‌های `-wal` و `-shm` در پوشه `storage` نرمال هستند.
- برای پشتیبان‌گیری کافی است فایل `storage/shop.sqlite` را دانلود کنید.

### تاریخ شمسی و اعداد
همه تاریخ‌ها با تبدیل شمسی داخلی (`jdate()`) نمایش داده می‌شوند و اعداد با
ارقام فارسی (`fa_digits()`، `money()`). ورودی فرم‌ها هم ارقام فارسی را می‌پذیرد.

### امنیت
- همه کوئری‌ها با **Prepared Statement**
- خروجی‌ها با `e()` (htmlspecialchars) فیلتر می‌شوند
- توکن **CSRF** روی همه فرم‌ها و درخواست‌های AJAX (هدر `X-CSRF-Token`)
- رمزها با `password_hash()` (bcrypt) و محدودیت تلاش ناموفق ورود
- آپلود تصویر با بررسی MIME، محدودیت حجم ۳ مگابایت و نام فایل تصادفی
- جلوگیری از اجرای PHP در پوشه `uploads`

### اتصال درگاه پرداخت واقعی
فایل `app/controllers/checkout.php` را ببینید:
- در متد `payment()` به جای صفحه شبیه‌ساز، کاربر را به درگاه هدایت کنید.
- در متد `payment_post()` پاسخ درگاه (Authority/Status) را با cURL بررسی و
  `payment_status` و `status` سفارش را بروزرسانی کنید.
- `Merchant ID` را از پنل → تنظیمات → «درگاه پرداخت» وارد کنید.

### سفارشی‌سازی ظاهر
- رنگ‌ها و فاصله‌ها: متغیرهای CSS در ابتدای `public/assets/css/app.css` (`:root`)
- نام فروشگاه، شعار و متن‌ها: پنل مدیریت → تنظیمات (یا `app/config.php`)
- تصاویر محصولات نمونه در `public/assets/img` قرار دارند؛ تصاویر واقعی را از پنل آپلود کنید.
- بعد از هر تغییر در CSS/JS مقدار `asset_version` در `app/config.php` را یک عدد بالا ببرید
  تا کش مرورگر بازدیدکنندگان تازه شود.

## ۷. PWA — نکته‌ها
- سرویس‌ورکر فقط روی `https` یا `localhost` فعال می‌شود.
- پس از تغییر در فایل‌های استاتیک، عدد `VERSION` در `public/sw.js` را بالا ببرید
  تا کش کاربران بازنشانی شود.
- آیکون‌ها در `public/assets/icons` هستند. منبع آیکون: `assets/img/icon-source.png`
  (با `sharp` در اندازه‌های ۱۹۲/۵۱۲/ماسکبل ساخته شده است).
- برای تست نصب: در Chrome → منوی سه‌نقطه → «Install app» یا روی موبایل «Add to Home screen».

## ۸. کارهای پیشنهادی برای مرحله بعد
- اتصال واقعی درگاه (زرین‌پال/آیدی‌پی) و ارسال پیامک تأیید سفارش
- انتقال دیتابیس به MySQL در صورت رشد تعداد سفارش‌ها
- سیستم انبار و ورود/خروج کالا، فاکتور رسمی PDF
- ورود با کد یک‌بارمصرف پیامکی (OTP)
- اتصال به API تأمین‌کننده برای بروزرسانی خودکار قیمت و موجودی
